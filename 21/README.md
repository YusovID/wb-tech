### Применимость паттерна «Адаптер»

Паттерн применяется, когда нужно заставить работать вместе объекты с несовместимыми интерфейсами.

*   **Использование сторонних библиотек:** когда интерфейс внешней библиотеки не совпадает с тем, который принят в вашем приложении.
*   **Интеграция с устаревшим кодом (legacy):** для "осовременивания" старых компонентов без их переписывания.
*   **Создание общего интерфейса:** когда нужно привести несколько разных классов к одному виду для клиента.

---

### Плюсы и минусы

#### Плюсы:
*   **Повторное использование кода:** позволяет использовать существующие классы, а не переписывать их функциональность.
*   **Изоляция:** клиентский код не зависит от конкретных классов, а только от целевого интерфейса. Логика преобразования скрыта внутри адаптера.
*   **Принцип единственной ответственности:** логика преобразования интерфейсов выносится в отдельный класс-адаптер.

#### Минусы:
*   **Усложнение кода:** в систему добавляется еще один слой в виде новых классов/структур, что может сделать ее менее прозрачной.

---

### Реальные примеры использования

*   **Драйверы баз данных:** в Go стандартный пакет `database/sql` определяет общий интерфейс, а конкретные драйверы (PostgreSQL, MySQL) являются адаптерами, которые "переводят" его вызовы в команды для своей СУБД.
*   **API-адаптеры:** создание единого интерфейса для работы с разными внешними сервисами (например, платежными системами Stripe и PayPal или мессенджерами Telegram и WhatsApp).
*   **Конвертеры форматов данных:** класс, который принимает данные в формате XML и предоставляет методы для их чтения как JSON, является адаптером.
